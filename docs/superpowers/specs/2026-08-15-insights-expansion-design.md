# Insights Expansion: Season Forecast, Calibration, Team Pages, H2H, Feature Reveal

Date: 2026-08-15
Status: Approved design (pending user spec review)

## Context

The site currently ships four pages (Matchday, Teams, Records, Method) powered by a Random Forest model trained on 5 seasons of Understat data (ELO ratings, rolling goals/xG). This expansion adds five features that deepen the "model as product" positioning for the data/ML audience:

1. **Season simulator** — Monte Carlo projection of the rest of the season
2. **Calibration dashboard** — Brier score, calibration curve, rolling accuracy
3. **Team detail pages** — profile, form, ELO history, upcoming fixtures
4. **Head-to-head** — meetings history + how the model called them
5. **"Why the model says so"** — per-fixture feature reveal

All data required already exists in-repo: `training_data.pkl` (5 seasons: goals, xG, ELO per match), `data/predictions/*.json` + `data/results/*.json` (this season's prediction-vs-result archive), `fetch_upcoming_matches()` (remaining fixtures + ELO), and the `predict_match()` feature pipeline (all 8 features computed internally today — just not exposed).

## Architecture

### Backend

**New module `backend/insights.py`** — pure, testable functions; no FastAPI coupling:

- `build_standings()` — reconstruct current-season table from `training_data.pkl` completed matches. Returns points, W/D/L, GF/GA per team, sorted.
- `simulate_season(n_sims=10_000)` — for each remaining fixture (from `fetch_upcoming_matches()`):
  - get model prediction via `predict_match()`
  - sample scoreline from Poisson using predicted lambdas (`home_goals`, `away_goals`)
  - accumulate standings across n_sims runs (seeded for determinism)
  - Outputs per team: title/top-4/top-6/relegation odds, points percentiles (P10/P50/P90), position distribution.
- `compute_calibration()` — pure math over archived predictions + results:
  - Brier score
  - calibration bins: predicted-probability buckets vs actual win rate
  - rolling accuracy per gameweek
- `team_profile(team)` — from `training_data.pkl`:
  - per-season W/D/L
  - last-6 form
  - ELO history series
  - all meetings vs a chosen opponent (head-to-head)

**New endpoints** (in `backend/server.py`):

| Endpoint | Source | Notes |
|---|---|---|
| `GET /api/season/forecast` | cached `data/forecast/<date>.json` | regenerated by morning automation job; on-demand regen fallback; degrades to last-known forecast if `fetch_upcoming_matches` unreachable |
| `GET /api/calibration` | on-demand from JSON archives | offline-capable, fast |
| `GET /api/teams/{team}` | `training_data.pkl` | offline-capable |
| `GET /api/teams/{team}/h2h?vs={other}` | `training_data.pkl` + this season's prediction archive | offline-capable |

**`predict_match()` extension:** include the 8 feature values (team codes, ELOs, rolling goals/xG) in the response payload. Ships in predictions going forward; enables the feature reveal without reprocessing history.

### Frontend

**Nav:** two new items — **Forecast** and **Calibration** — added to the running head. Teams becomes a roster index linking to per-team pages.

- **`/forecast`** (`ForecastPage.tsx`) — projected final table: position bands, title/top-4/relegation odds bars, expected points with P10–P90 range.
- **`/calibration`** (`CalibrationPage.tsx`) — Brier score card, calibration curve (predicted-prob buckets vs actual win rate), rolling accuracy per gameweek chart.
- **`/teams/:slug`** (`TeamDetailPage.tsx`) — season record, last-6 form strip, ELO history line (5 seasons), upcoming fixtures with model verdicts, head-to-head picker → all meetings + model calls for this season's meetings.
- **`FeatureReveal` component** — expandable on matchday cards and team-page fixtures: 8 feature values vs league average. Client-side comparison math.

**Charting:** hand-rolled SVG charts in the existing almanack/broadcast design language. No chart library (none installed; stock-library look would break the aesthetic).

## Data flow

- Forecast: morning GitHub Action runs `simulate_season()` → writes `data/forecast/<date>.json` → API serves cache. Missing/stale file → regenerate on demand. Empty (end of season) → "season complete" state showing final table + season accuracy.
- Team pages / H2H / ELO history: direct from `training_data.pkl`, no network on request path.
- Calibration: on-demand from JSON archives.

## Error handling

- Unknown team slug → 404 with existing `EmptyState`/`OfflineSlate` pattern.
- No remaining fixtures → "season complete" state (final table + this season's accuracy).
- Backend offline in dev → existing offline states on all new pages.
- Missing `training_data.pkl` on prod → null values with clear messaging, no crashes.

## Testing

- Backend (pytest): `simulate_season` sanity (probabilities sum to 1, position distributions sum to 20 teams, seeded determinism), standings math, calibration math on a small hand-built fixture set, cache read/write.
- Frontend: `npm run build` + lint, manual route checks (no existing test harness).

## Scope

One spec, one plan, one build. Five features, four new endpoints, one new backend module, two new pages + one absorbed (Teams → roster + detail).

## Out of scope

- Betting odds comparison, sharing cards, PWA, email digests, public API docs (parked from brainstorming; not part of this build).
- Changing the model itself or retraining pipeline.
- Player-level stats (data is team-level).
